## Design Context

### Users
A single technical operator (platform engineer / developer) who both runs and debugs the `easy-bpmn` saga
orchestrator. They use the **read-only** console to watch distributed sagas across their microservices, audit a
humanized timeline, view the BPMN diagram with live execution state, and act (`cancel`/`retry`) on the rare
failures. Context spans daytime ops and on-call. No RBAC — one credential, one set of screens. The high-stakes
moments are debugging failing distributed transactions, but the **dominant case is watching the system work.**

### Brand Personality
Alive · precise · composed. A trustworthy *instrument*, not a marketing landing and not a toy. Affirmative by
default: it shows that things work. "Restraint earns trust" — distinctiveness comes from typography, space, and one
signature, never from scattered effects.

### Aesthetic Direction
**"Living Systems"** — the saga's BPMN process is the hero, rendered as luminous flowing current: tokens travel as
soft light, the traversed path illuminates as the saga runs, the circuit settles on success; a timeline ribbon
scrubs the flow to replay. **Light theme only** (firm — a deliberate `dark→light` choice). Cinematic-on-light means
**luminosity on a pale field, never neon-glow-on-dark.** Teal `#109b86` is the brand *and* the color of live
current; node runtime-state stays semantic (running-blue / completed-green / error-coral); the **BPMN category
palette is frozen and load-bearing** (read the canvas by colour). Type trio replaces system fonts: **Clash Display**
(display) · **General Sans** (UI) · **Commit Mono** (data) — all free/self-hostable, finalize in `craft`.
**Health is the hero; trouble is rare, sharp punctuation.**
**The IA is diagram-first:** the console opens directly onto a process's living diagram — a single **"Process Stage"**,
with no Projects/Sagas/transaction-list landing screens. Switching process, dropping into a specific instance, and
finding a transaction are **controls** (incl. a **⌘K command palette**), not screens.
*Anti-references:* dark glowing observability dashboards; dashboard-kit stat-tile soup; busy multi-panel admin UIs;
landing/list "router" screens; playful/bouncy motion.

### Design Principles
1. **One living hero on a calm field** — simple structure; richness reserved for the single focal flow. Cinematic ≠ busy.
2. **Light, luminous, not neon** — the cinematic quality is luminosity on pale, never glow-on-dark.
3. **Health is the hero** — show the system working; surface trouble sharply and rarely.
4. **Current = teal; node state = semantic; category palette frozen** — chrome never competes with node meaning.
5. **Motion only for the flow + functional state feedback** — and `prefers-reduced-motion` must be fully legible
   (no information may live only in animation); no bounce/elastic; `transform`/`opacity` only.
6. **Calm by default, dense on demand** — progressive disclosure; the mono data layer carries the rigor.
7. **Restraint earns trust** — distinctive through type, space, and one signature, not effects. Honor the impeccable
   absolute bans (no side-stripe accents, no gradient text, no glassmorphism-everywhere, no hero-metric template).
